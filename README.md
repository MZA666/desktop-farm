# 桌面农场

Windows 11 x64 本地像素风放置游戏，当前版本0.8.6（商店卡顿修复版），保留0.8.5的种子搜索与筛选恢复，以及0.8.4的左右补地块、就近派工与面积渔网。Godot4.7.2、GDScript、C/Win32 GDExtension。独立场景背景、作物分期、动物/农夫动作使用原创生成像素素材，中文使用系统字体。

## 试玩

双击 `dist/DesktopFarm-v0.8.6/DesktopFarm.exe`，保持同目录的 `.pck` 和 DLL 文件。无需安装Godot、Python或编译器。「种子商店」按数量购买入库并选择默认自动订购；「种子库」选择品种后在农田点击、框选或按Shift多选地块，提交种植安排。当前作物完成本轮后换种，取消安排释放预留种子。整个可用库为空才自动订购，其他库存按固定品种顺序继续播种。

种子搜索框右侧的×只清空关键词。「清除筛选」同时清空搜索、季节、类型和“只看已解锁”条件，并回到列表顶部；种子库恢复全部有库存的种类，种子商店恢复全部53种作物。库存种类变化时列表会同步更新。

默认展开420逻辑像素，可切换紧凑240或收起工具栏。农场、牧场和鱼塘分开呈现；动物按真实坐标走出棚舍、觅食、进食，点击互动有成长/产出加成及持久化冷却。鱼首次捕获自动消耗登记，此后直接自动出售，全程不弹结果确认；鱼塘入口可独立升级收网速度、渔网范围和鱼塘容量，最高5秒冷却、36条容量、一次最多4条。点击水面或拖动定位，松手按圆形范围捕获；同网新鱼种消耗首条登记，余鱼自动出售。

每块地独立管理，初始24、最多100块；建设中每次开垦一块。设置可调农夫速度16～48像素/秒，默认32；按实际距离行走，到达后才开始2秒动作。所有游戏窗口遵循普通 Windows 前后顺序，点击其他应用后该应用优先显示。

托盘菜单和 `Ctrl+Alt+F` 可显示/隐藏游戏，同显示器前台全屏应用会暂时隐藏全部游戏窗口；后台生产继续。快捷键占用时显示明确提示，可继续使用托盘。仅收起场景时工具栏仍可经营。

窄屏下商店快捷按钮会收进经营首页，托盘也能直接打开两个商店。

玩法说明见[试玩说明](docs/play-guide.txt)，地块、派工及渔网玩法见[0.8.4开发规格](docs/development-spec-v0.8.4.md)，当前验收见[0.8.6验收记录](docs/validation-v0.8.6.md)。完整生产规则仍见[0.8.2开发规格](docs/development-spec-v0.8.2.md)；本次商店响应测量见[0.8.6商店性能报告](docs/shop-performance-v0.8.6.md)。整款游戏的CPU及内存占用仍参考[0.8.4历史性能基线](docs/release-performance-v0.8.4.md)，不能据此认定0.8.6全部性能目标已达标。美术来源见[素材提示词](assets/pixel/v0.8.2/generation-prompts.md)，本轮沿用这些素材。

便携试玩压缩包为 `dist/DesktopFarm-v0.8.6-win64.zip`，解压后启动程序。包中附开发文档和验收记录。启动前先正常退出旧版游戏；首次载入有效v1/v2/v3/v4/v5旧档会验证并创建不可覆盖的版本备份，再迁移为v6，保留金币、库存、任务领用及生产进度。0.8.6继续使用v6存档，可直接延续0.8.4或0.8.5的进度。

## 源码运行与构建

0.8.6修复商店打开及报价刷新的卡顿：购买预览不再为每张作物卡片重复恢复并校验完整存档，报价仅在相关种子预算输入变化时更新。优化前的满规模0.8.5源码测试中，单次商店刷新耗时4.6～5.2秒；优化后的测量和范围见商店性能报告。正式经营操作仍执行原有校验、保存及失败回滚。

0.8.5已修复种子搜索的清空入口、组合筛选重置、经营页滚动位置，以及库存种类变化后的列表刷新；本版保留这些功能，不改0.8.4的生产和升级规则。

0.8.4新增：保留原96格位置及54×40大小，在泥土左右追加4格；增加清晰的缺水/成熟标记和待收/缺水/待播统计；同优先级农场工作优先走最近的实际可达路线，保留等待公平性。渔网半径20/29/35/40，按面积最多捕获1/2/3/4条，升级300/700/1500金币。动物悬停显示实时奖励冷却和额度，产物拾取及卖鱼显示收益。地形缓存与动态角色分别更新。成品测量可用 `./scripts/measure_release.ps1`，默认读取当前项目版本，使用隔离测试存档。

首次准备：

```powershell
./scripts/setup_toolchain.ps1
./native/build.ps1
./scripts/run.ps1
```

工具只下载到 `.tools/`，不安装到系统。首次准备需要网络；准备脚本固定使用已验证的 Godot 4.7.2 与 Zig 0.16.0，本机工具路径和校验值写入 `.tools/toolchain.json`。该文件不进入 Git，新电脑重新运行准备脚本。

```powershell
./scripts/test.ps1
./scripts/run.ps1 -Editor
./scripts/build.ps1
```

只更新随包说明、保留已经测量过的EXE/PCK/DLL时，可执行 `./scripts/build.ps1 -PackageOnly`；该参数不会编译源码变化。

Windows 导出需要 `.tools/export-templates/` 中与引擎版本一致的官方模板。安装 Python 3 后，在项目根目录执行一次：

```powershell
python ./scripts/download_windows_templates.py
```

该脚本从官方模板压缩包通过 HTTP Range 只提取 Windows x64 文件，逐文件校验 ZIP CRC 并保存下载收据。完整压缩包没有下载，收据中的整个包 SHA256 不作为已验证结果。发布打包使用真正的导出模板。

配置核验：用 Python 执行 `tests/validate_config.py`。原始数值导出脚本 `scripts/export_config.py` 读取已纳入 Git 的 `data/source/workbook-v0.5.json`，玩法运行不依赖原 Excel 或 Word。逻辑测试覆盖全部内容 ID 及满规模存档恢复；图形和原生验证的实际结果单列。

源码、设计文档、数值来源和测试纳入 Git；工具、缓存、截图及 `dist/` 试玩包由本机构建生成。提交与远端同步步骤见 [Git 维护说明](docs/git-workflow.md)。

## 存档

正式试玩保存于Windows用户目录的Godot `app_userdata/桌面农场/desktop-farm-save.json`。设置可打开实际目录。30秒自动保存，经营操作立即保存；写入失败撤回操作。退出与休眠暂停，没有离线收益。损坏主档尝试完整.bak，两份均坏时暂停并保留文件。迁移备份version-v1/v2/v3/v4/v5不可覆盖；迁移写入失败停止启动。旧版无法读v6，回退需全部游戏退出后使用对应原版备份。测试及录制使用独立test-data存档，不使用正式玩家文件。

原始需求、数值来源及已确认变化记录在 `docs/requirements-review-v0.5.md`。源码目录 `.review/`、`.tools/`、测试、截图及原始文件不随试玩包发布。
