# 桌面农场 0.8.2 开发规格与验证记录

日期：2026-10-03。基线：0.8.1，提交 `04e0209f15e3ad8bf1f918b276368ab1eaedd6e9`。用户已批准完整开发，并明确采用“产物落地立即进入下一轮，允许多份积累”。规划原文保留在 `optimization-plan-v0.8.2.md`，本文件记录实际实现契约与验证证据。

## 核心生产与固定产物

模型仍以 0.2 秒固定步长推进，仅计算游戏进程有效运行时间，没有离线收益。11 种动物继续使用原配置的成长时间、生产间隔、价格与食物消耗；饥饿暂停当前成长和生产，不删除已掉落物。

动物 `production_cycle` 表示当前生产轮次，从 0 开始；`last_drop_cycle` 表示最后已掉落的轮次，初始为 -1，始终等于 `production_cycle - 1`。普通计时与互动提前完成均进入 `FarmGroundProducts.complete_cycle`：在确定性安全落点增加一份库存，记录来源和本轮编号，再将轮次加一、产物倒计时重设为该品种完整间隔、成年本轮互动加成额度清零。重复调用不能重复掉落。幼年总加成额度不因成年生产循环而重置。

个人 120 秒和全局 2 秒互动冷却继续有效，落地与拾取均不清除已使用的冷却。已存在地面物品不阻止下一轮互动；饥饿反馈不消费奖励额度。v4 不再使用 `ready=1` 表示等待领取，现存动物 `ready` 保持 0，`held_by` 为空、`hold_remaining` 为 0，领取产物不会使动物暂停活动。

`state.ground_products` 保存物品堆列表；`get_ground_products()` 提供同一列表供界面读取。每个物品堆如下：

```text
{
  id, product_id, name, x, y, quantity, queued_at,
  batches: [{id, source_type, source_animal, sell_price, quantity,
             queued_at, first_cycle, last_cycle}],
  claims: [{id, farmer_id, batch_id}]
}
```

`x/y` 是牧场世界像素的固定地面坐标，来自 `World.product_drop_position` 的有限安全格点：58 列 × 9 行，共 522 个落点。不同产品在同一落点可分别成堆，同产品同落点合并。合并不移动原堆；同来源动物、品种和售价的库存累加为一个批次，避免为每份产物创建常驻精灵或存档对象。数量没有人为上限，不静默丢弃；`quantity` 等于所有批次数量之和，并包含尚未完成的认领份数。来源动物已售出是合法状态。

落地不提前增加金币或登记图鉴。兔与羊的毛束可以合堆，但其来源类型、售价及原动物编号保存在不同批次中；领取时按该份所属批次结算，图鉴保留两种来源。

## 自动领取与结算

任务仍使用 `action="collect_product"`，`target` 改为物品堆 ID，并追加 `claim_id`、`batch_id`、`claim_farmer_id`。认领使用独立唯一编号，仅锁定一个份额，不先扣库存。两个农夫可以认领同堆的不同份额；每位农夫至多持有一份地面产物认领。现有牧场优先级、体力恢复及支援规则继续使用。

农夫沿真实路径到达固定落点，不追踪来源动物。路径终点、任务目标和物品堆位置统一；到达后每次领取恰好用时 2 秒、消耗 1 体力。完成时删除唯一认领标记，扣一份批次及总库存，增加该批次售价，并登记/增加图鉴收集数量。再次执行相同任务不会重复结算，也不会额外扣体力。清空的批次和物品堆删除；其他有效认领保持可用。

固定物品任务不再使用旧追逐动物的 120 秒总任务超时；已累计超过这一旧阈值的有效迁移任务仍按保存的剩余动作完成，不能被取消后重新计满 2 秒。

取消任务、路径失败或无效旧认领只释放份额，不扣库存、不增加金币。恢复存档先核对任务与认领的互相绑定，释放孤儿或重复认领；多余旧任务变为空闲。库存数量、来源结构或价格损坏仍拒绝读档，不以“释放认领”为由悄悄修正坏库存。

出售动物只按标准购价 50% 退款，释放未消费的食物预约。地面产物、固定位置及领取任务全部保留，出售不提前卖掉这些物品。界面出售预览必须只显示退款，并说明地面产物保留。

## v4 存档与兼容迁移

当前 `FarmState.SAVE_VERSION=4`，保存独立 `layout_version=4`。v4 保存所有固定物品堆、来源/售价批次、逐份认领、动物循环状态、农夫路径/剩余动作、鱼运动状态和独立随机流。所有新增编号共享原 `next_id`，验证其唯一性及编号上限。

升级链为 v1 → v2 → 冻结 v3 → v4。`world_layout_v3.gd` 保留原 0.8.1 几何；先使用该几何审查旧路径，再按当前布局转换，不能用新坐标否定原本有效的旧档。

- 每只 v3 `ready=1` 动物转换成恰好一份产物，保留旧 `queued_at`，加载时采用动物附近安全落点，立即开始下一完整轮次并清除旧收取冻结。未成熟动物保持剩余成长/生产及独立食物认领。
- 旧收取任务的动物 ID 转为对应物品堆、原来源动物批次和唯一份额。兔羊同落点合堆时，仍认领原任务动物的批次，不依赖批次列表或农夫列表顺序。行走中保留可通行当前位置后重新寻路；作业中校准到物品位置并保留剩余动作时间及已累计任务时间。两个旧任务指向一份产物时保留一个有效认领，其余释放，不制造第二份产物。
- 地块 ID、开垦数量/顺序、作物阶段、剩余时间、已有产物、返还种子、待换作物和种子预留保持。农场行走任务按地块 ID 重寻路，已到达作业任务移动到新工作点并保留动作时间；已付种子不重复扣款。牧场加料、割草、播草及整餐食物认领保持，不能因农田重排而统一重置。
- 旧鱼使用冻结 v3 水域矩形还原归一化位置；安全位置保留，越界位置确定性投影到最近安全水点。保留鱼 ID/种类/数量、鱼苗及渔网剩余时间、升级、图鉴、金币和随机流。不触发捕鱼结算，也不消耗随机数。

迁移在独立副本完成并严格验证。持久化前先保留原文件的唯一 `version-vN-...json` 备份，检查 SHA256 一致后写入新档；常规备份和后续保存不能覆盖这份原档。新档经临时文件写入、刷新及校验后原子替换。写入失败保留原档并返回明确错误；不得因此退回更旧进度。重试迁移不会重复掉落或结算。

JSON 使用 `full_precision=true` 保存浮点数，防止世界像素坐标和剩余时间在写入/读取中丢失精度。保存前检查模型状态，数量不守恒等坏状态不写入主档。高于当前或任何不支持的版本拒绝读取，也拒绝被当前版本的普通 `save` 覆盖；不会为打开成功而降级读取旧备份。

旧 `pending_fish` 继续作为独立兼容状态保留；`restore()` 不自动兑现。控制器通过显式 `resolve_pending_fish` 一次结算并保存，保存失败恢复整个快照，后续保存重试继续这一命令。保持首次消耗登记、已登记直接出售规则，两个鱼塘倒计时不重置。

## 鱼出生与持久运动

v4 活鱼的 `x/y` 为鱼塘世界像素，并保存 `previous_x/previous_y`、`target={x,y}`、`heading`（弧度）、`phase`（累计游动秒数）、`swim_index`（确定性目标序号）。`FarmFishMotion.initialize/step/validate` 负责纯模型运动；相机、切场、紧凑模式和渲染帧率不改变轨迹。

出生使用原鱼类随机选择与两个位置随机样本，再调用 `World.sample_fish_position`。追加鱼之前检查完整鱼身处于安全水面；失败不追加无效鱼，不谎报成功补苗。运动选择每条鱼 ID 与序号决定的短目标，不消费任何生产随机流；完整线段须通过 `World.fish_segment_safe`。每个固定步长只沿一段已验证路径移动，避免渲染插值在转角处切过岸边。位置、朝向和游动时间量化到 1e-6。

界面直接插值已保存的 previous/current 世界位置，或读取 `World.fish_visual_position`；不得再叠加未验证的正弦漂移。鱼身、当前点、上一点与当前目标线段在存档校验中统一检查。船、码头及陆地排除由独立水域标注提供。有效拖网线段与实际可见鱼一致，岸上按下/点击应由输入层拒绝，不进入空网冷却。

## 窗口、动画与最终集成

控制栏为主场景所在的根 Window，具有正常激活能力及 APPWINDOW 身份；工具栏控件挂在 main 场景节点，在根窗口绘制，避免成品加载期间向忙碌根节点增添控件失败。独立场景为根的 owned TOOLWINDOW/NOACTIVATE 窗口；经营面板同样所属根窗口。根32逻辑像素，场景物理位置在根下方，展开/紧凑总高度420/240，地图实际352/172。窗口可見性刷新不激活、不抬升已显示窗口；根最小化时保留任务栏入口，所属内容与渲染暂停，逻辑生产继续。

边景使用0.8.2独立原创林地/池岸图，左右各绘一次连续区域，不复制主体场景的建筑或岸景窄条。装饰接缝48像素过渡；世界坐标、土壤及水域校验仍以原主体图为准。

木牌锚点按七座建筑山墙实际标注，显示主要动物头像及总数/容量。特殊动物用所属棚位合计，悬停显示各品种组成，点击未建棚进入建设，已建棚进入过滤后的动物管理。地面产物按固定坐标参与足点深度排序，28×28图标，数量大于1时显示小库存牌。

农夫原步行动作每方向4帧，运行每原帧保持两相位共8相位；上向源顺序为0/2/1/3，其他方向0/1/2/3。每移动3世界像素推进一相位，一周期24像素；相机移动不推进，闲置使用中性站姿。拾取8帧。所有脚点为(32,78)，绘制64×80。画面尚在插值抵达前继续步行，抵达后才显示作业动作；跨障碍采样用安全绕行路径，不从端点直穿建筑。

鱼显示优先插值当前画面至模型目标的安全路线。两次界面采样跨多个转角时若连接不安全，则使用该鱼持久化的previous/current末段，不跨岸。拖网只保留实际水面的有效区间，同一手势命中多个区间仍仅保留首条鱼。

最终图形回归4,417项通过；最终工具栏层级真实首点100/100和实际main最小化326项通过；正式EXE完整烟测退出0。证据、截图及未测设备组合见 `validation-v0.8.2.md`，成品CPU/内存见 `release-performance-v0.8.2.md`。模型测试不替代这些视觉与桌面验收。
