状态：用户已于 2026-10-03 明确要求“按照设计文档进行开发吧”，完整范围已获确认。七项功能已实现，正式EXE检查通过，最终记录见 `development-spec-v0.8.2.md`、`validation-v0.8.2.md` 与正式试玩包；CPU/内存目标尚未达到，实测及未测设备组合分别列出。

## 1 目标和优先级

本轮处理用户试玩反馈及补充的七项内容：农场与鱼塘重复边景、扩建农田超出泥土地面、畜栏动物类型与数量标识、控制栏点击及任务栏入口、鱼的水面活动边界、农夫左右腿步行动画、牧场产物落地与自动拾取。

优先级：先解决控制栏输入与窗口管理，再统一农田/水面边界，随后完成牧场产物规则、边景、步态和畜栏标识。农场、牧场、鱼塘继续分开显示，采用现有概念图对应的像素田园风格。

新增生产规则已由用户明确选择：**产物落地后立即开始下一轮，允许多份产物积累**。这一选择覆盖旧版“每只动物一份待收，收完再生产”的规则，属于本版确定的玩法调整，随完整范围一起开发。

| 问题 | 已确认事实 | 下一版目标 |
| --- | --- | --- |
| 农场及鱼塘左右边景重复 | 宽屏补边反复复制背景窄条，含鸡舍、围栏或岸石/芦苇 | 自然连续的边景，建筑与岸景不出现明显重复 |
| 底部农田进入草地、道路 | 逻辑地块矩形与实际泥土边界不一致 | 初始和扩建后的全部地块完整落在泥土内 |
| 畜栏难以辨认 | 现有建筑没有对应动物头像和数量牌 | 每座畜栏显示头像及数量/容量，支持混养的特殊动物 |
| 控制栏需从任务栏重新激活 | 场景和控制栏被拆成独立原生窗口，输入故障尚未真实复现 | 一个主要应用入口，直接点击可见控制栏即可操作 |
| 鱼游到岸上 | 鱼出生和显示漂移只按大矩形计算，未扣除曲岸、船和码头 | 鱼苗及所有游动中的鱼身完整留在真实水面 |
| 农夫只明显摆动一条腿 | 运行图集多个帧仍是同一腿前摆，且步频由全局时间固定驱动 | 四方向左右腿交替，步态与真实行走速度协调 |
| 农夫追动物收取产物 | 待收产物记在动物身上，没有独立地面物品 | 产物静止落地，动物连续生产，农夫拾取独立产物 |

## 2 控制栏与应用窗口：最高优先级

### 2.1 原因分析与证据边界

当前是一个游戏进程创建场景、控制栏和经营面板等多个原生窗口，不是两份游戏实例。代码主动取消控制栏、经营面板的窗口所属关系，且场景和控制栏的窗口矩形在顶部重叠。

已确认需要整理窗口身份、所属关系、激活策略和点击区域。偶发失灵可能涉及重叠窗口命中、第一次点击被用于激活、观察/收起后输入状态不同步或拖动捕获未释放；这些需要在开发阶段记录实际鼠标事件后判断，不能把某一种猜测写成已确认根因。

现有界面自动检查有直接触发按钮信号的步骤，只能验证切场业务逻辑。此前受锁屏影响的真实桌面检查也未覆盖用户当前描述的可靠操作链；本轮必须新增真实点击验收。

### 2.2 推荐方案

- 将控制栏作为稳定的主窗口，任务栏只保留一个“桌面农场”主要入口；Alt+Tab 同样只有一个主要游戏入口。
- 场景与经营面板归属该主窗口。内部保留独立渲染窗口，以支持观察模式穿透、收起后控制栏刷新和独立经营面板。
- 场景位于控制栏下方，物理窗口矩形不重叠；展开、紧凑、收起的总高度继续分别约为 420、240、32 逻辑像素。
- 控制栏允许正常激活，始终接收鼠标；场景按观察/交互模式设置输入策略，不单独占用任务栏。
- 集中管理显隐、位置、窗口样式和所属关系，减少显示状态与输入状态不同步。经营面板关闭、模式切换、焦点丢失或捕获中断时及时结束拖动/框选。
- 拖动只由明确的握柄触发，按钮点击不会被拖动处理消耗。
- 用户点击其他应用后，其他应用优先展示。窗口恢复不通过定时抢焦点、永久置顶来实现。

开发先记录点击命中的窗口、前台窗口、窗口所属关系与样式、鼠标按下/抬起、按钮事件和切场结果，再结合记录修正。整理任务栏入口与修复点击可靠性分别验收。

### 2.3 技术依据

微软文档说明：`WS_EX_APPWINDOW` 会强制顶层窗口出现在任务栏；`WS_EX_TOOLWINDOW` 用于不出现在任务栏/Alt+Tab 的工具窗口；`WS_EX_NOACTIVATE` 影响点击时的激活行为。因此需要明确每类窗口的样式，而非只解除所属关系。[扩展窗口样式](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles)

从属窗口始终高于所属窗口，故新增所属关系时必须同时消除场景与控制栏的物理重叠。[窗口所属关系](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)

首次点击的激活与是否保留鼠标消息还受 `WM_MOUSEACTIVATE` 处理影响，需要与 Godot 实际收到的事件共同检查。[鼠标激活消息](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mouseactivate)

## 3 农田边界与扩建布局

### 3.1 已确认原因

当前地块从 `(352,112)` 开始，以 16 列 × 6 行、56 像素间距排列，范围到 `(1248,448)`。最后一行覆盖 `y392..448`，而背景部分泥土地面在约 `y380..405` 就已结束，导致土块、幼苗和工作目标进入下方草地/道路。

仅遮住越界的画面不能解决问题：点击范围、作物位置和农夫作业目标仍可能留在原坐标。现有布局检查仅比较程序自己的农田矩形，也不能发现与背景不一致。

### 3.2 推荐方案

1. 为当前农场背景人工标注可耕泥土边界，形成与美术资源版本绑定的土壤区域。道路、田埂、草地、建筑不作为可耕范围。
2. 在该范围内预先安排 96 个稳定地块槽位。优先评估更紧凑的 16 × 6 排列，地块占地改为合适的矩形；准确间距在叠加边界和实际作物后的引擎画面中确定，不直接沿用 56 × 56 的占地。
3. 每个地块的完整土面及边缘安全余量都必须在允许区域内，不能只检查中心点。开垦顺序从这套已验证槽位中选择，初始 24 块与扩建上限 96 块保留。
4. 地块土面、湿土、选中框、点击范围、作物根部和农夫工作目标统一取自同一份布局数据。作物枝叶可高于土面，但根部落在对应地块内。
5. 作物、农夫的显示比例保持统一；通过地块间距和田内排列解决越界。农夫仍可在田外道路行走或休息。

### 3.3 旧存档迁移

保留地块 ID、已开数量、扩建顺序与价格。已开地块按原 ID 迁到新的合法位置，保留金币、种子库存/预留、作物品种、阶段和剩余时间，避免重开档。

现有存档为 v3，布局版本没有独立保存。下一版建议使用 v4 存档并明确保存布局版本；新增冻结的 v3 布局用于校验和迁移旧坐标。迁移前保留不可覆盖的原档备份，通过验证后再写入新档。

- 农场中执行种植、浇水或收获任务的农夫：正在行走时保留可通行的当前位置，按原任务地块 ID 重新寻路；正在作业时对应到新工作点，保留剩余动作时间与任务认领。
- 农田重排不处理牧场和鱼塘农夫的坐标。割草、播草、加料等任务及饲料/牧草认领保留；牧场旧收取任务按第 8 节转换为地面产物拾取。鱼塘范围修正若使旧路径不可通行，只重新寻路并保留有效任务与剩余时间。
- 迁移不重复扣种子、不重复收获，也不因旧路径终点失效而取消已支付的种植。
- 全部 96 个地块的产物、返还种子、待切换作物和种子预留一并核对。牧场、鱼塘、图鉴、互动冷却和其他经营状态继续保留；读取失败时给出明确恢复信息，不能悄悄清档。
- 保留现有 v1、v2 存档的升级能力，并拒绝将高于当前支持版本的存档降级读取。

## 4 左右边景与宽屏显示

当前补边复制农场原图最左侧约 92 像素的条带，里面包含鸡舍、围栏等明显物体。鱼塘也使用同一算法，左右条带中的树木、岸石和芦苇反复出现。屏幕越宽，重复越明显。原始农场背景本身没有这些重复鸡舍。

下一版去掉包含建筑的条带平铺，制作与场景衔接的独立树林、草地、石块和野花边景。具有明确轮廓的房屋、棚舍、围栏连接点不作为重复补边单元，接缝处保持光照、像素比例与地面连续。

同时检查三个场景的左右补边。宽屏显示自然边景；窄屏通过镜头浏览保持实体清晰。边景属于装饰，不扩大可耕地、牧草容量或鱼塘水域，也不截获经营点击。

## 5 畜栏动物头像与数量

为牧场 7 座畜栏分别添加小木牌，放在真实建筑屋檐附近。木牌常驻内容为动物头像和“数量/容量”，例如牛头像旁显示 `2/4`；字号和木牌尺寸统一，保持像素风。

| 畜栏 | 常驻主头像 | 特殊动物处理 |
| --- | --- | --- |
| 鸡棚 | 鸡 | 虚空鸡、金鸡存在时附加小头像 |
| 鸭棚 | 鸭 | 恐龙存在时附加小头像 |
| 兔棚 | 兔 | 显示本棚总数/容量 |
| 牛棚 | 牛 | 鸵鸟存在时附加小头像 |
| 山羊棚 | 山羊 | 显示本棚总数/容量 |
| 羊棚 | 羊 | 显示本棚总数/容量 |
| 猪棚 | 猪 | 显示本棚总数/容量 |

数量按动物的归属畜栏统计，包含幼年、成年、外出觅食和饥饿动物；不根据当前是否站在房屋里判断。特殊动物与普通动物共享容量，主牌显示合计数量。

未建畜栏显示灰色头像和小锁。悬停木牌时显示畜栏名称、等级、各品种数量；不增加长段常驻文字。点击打开现有动物管理并自动筛选所属畜栏；未建棚引导至建设扩展。交互范围避开自由活动动物的点击区域。

买入、出售、扩容、读档后立即刷新数量。动物走动不触发背景重建。每个木牌按实际背景中的房屋单独标注锚点，不能直接用等距的模拟棚位代替美术位置。

## 6 鱼塘实际水面与游动边界

### 6.1 已确认原因

现有水域是 `(320,96,1130,324)` 的大矩形。初始鱼和补苗在其归一化范围内随机生成，显示时又加约横向 ±79、纵向 ±11 像素漂移，未检查背景真实水面。

码头和船体与该矩形相交。例如归一化位置 `(0.05,0.5)` 对应世界坐标约 `(376.5,258)`，实际在码头上；`(0.05,0.2)` 对应约 `(376.5,160.8)`，实际在船体上。鱼身显示大小为 46 × 30 像素，仅限定中心点仍可能让头尾越岸。

### 6.2 推荐方案

- 按鱼塘背景人工标注真实可游水域，排除陆地、码头、船体、岸石及岸边草丛；标注绑定背景版本，不按颜色临时猜测水域。
- 将鱼身占地及安全余量纳入水域检查，得到鱼中心的安全活动范围。三种鱼、初始投放、补苗、游动目标和绘制位置共用这一范围。
- 运动检查完整路径。两个水内点之间的直线也可能穿过曲岸或码头，不能只检查起终点；靠岸自然减速/转向，不通过突然移动到安全点来掩盖越界。
- 游动及显示漂移保持在合法水域内，暂停、切场、紧凑模式和重启后的表现一致。存档保存必要的鱼位置/游动状态，读取后不重新随机投放。
- 捕鱼从真实水面开始，拖网只在有效水面段命中。当帧可见鱼与命中位置一致；岸上点击不捕获鱼、不产生金币或空网冷却。鱼塘升级、首鱼自动登记并消耗、已收录鱼直接出售沿用既定规则。
- 农夫不能穿越水面；码头作为允许行走的独立区域，使用相同美术边界校准可通行区域。

### 6.3 旧鱼位置迁移

用冻结的旧矩形还原 v3 鱼位置；在新水域内的保留，越界鱼按确定性规则迁到最近安全水点。保留鱼 ID、品种、数量、鱼苗与渔网剩余时间、升级、图鉴、金币及随机流状态。

迁移不重新生成鱼、不额外消耗随机数、不触发登记或出售。无法完成安全迁移时报告失败并保留原档。

## 7 农夫左右腿步态

检查原始人物图与运行图集后，发现多个行走帧仍是相同一条腿向前，左右交替不足。当前播放逻辑以全局时间每秒 6 帧循环四帧，没有按每位农夫的真实位移调整步态；后者也是不同速度下滑步的风险，需要在引擎中验证。

下一版保留草帽、蓝色工装及现有人物比例，重新制作四方向完整行走周期，建议每方向 8 帧。周期覆盖左脚前摆/着地、支撑过渡、右脚前摆/着地和另一侧过渡，左右腿和相反方向的手臂运动清楚可辨。

- 每帧保持人物外形、脚底锚点、光照和比例一致，不以帽子抖动代替腿部变化，避免脚被裁掉。
- 每位农夫有独立步态相位，以真实行走距离驱动；快慢设置改变步频，停止时回到站立帧，转向时保持连续。
- 到达后再播放作业动作；新增弯腰拾取/起身动作，用于地面产物收集，与挥镰收作物区分。
- 行走速度设置与实际距离耗时仍使用现有规则，动画改进不缩短路程或跳过工作时间。
- 在正式游戏录制前后左右四方向的正常速度、慢速、转弯与停止片段，逐帧检查左右腿交替、切向、插值和脚底稳定性；同时检查 15/30 帧模式。

## 8 牧场产物落地与连续生产

### 8.1 当前流程与新流程

当前动物产出完成后只设置 `ready=1`，农夫任务目标为动物 ID，沿途追踪动物位置；靠近后动物暂停活动，收取才结算并开启下一轮。当前没有独立地面产物。

本版按用户选择改为：**饱食动物完成本轮 → 产物落地 → 立即开始下一轮；农夫另行认领地面产物 → 走到固定位置 → 拾取并自动出售/登记图鉴。** 未拾取产物允许多份积累，不阻止动物后续生产。

| 动物 | 落地表现 |
| --- | --- |
| 鸡、鸭 | 对应鸡蛋、鸭蛋 |
| 牛、山羊 | 对应牛奶桶、羊奶桶 |
| 兔、绵羊 | 沿用当前配置中的毛束产物 |
| 猪 | 松露 |
| 虚空鸡、金鸡、恐龙、鸵鸟 | 各自对应的特殊蛋 |

所有 11 种动物均接入同一规则。产物生成在动物当时附近的可通行地面；若位置被障碍占据，使用最近可达的安全落点。落点不能在建筑内、水里或地图外。生成后位置固定，动物走远也不移动产物；切场、镜头、收起和重载不改变落点。

### 8.2 数量积累、认领与结算

- 产物不变质、不因无人拾取而消失；饥饿仍暂停动物当前生产进度，已落地产物保留。维持无离线收益的现有规则。
- 邻近同类产物可显示为数量小堆，避免积累后铺满图标。合堆保留产品、来源类型、售价及各批次信息；兔和绵羊同产毛束，也要保留正确图鉴来源。
- 已有物品堆位置固定，新掉落并入后只增加数量。采用有限的安全落点和数量存储，大量积累不要求每一份都有常驻精灵，也不静默丢弃超量产物。
- 农夫自动认领一份产物，按真实距离走到固定落点；到达后拾取一份用时 2 秒、消耗 1 体力。继续使用现有任务优先级、休息及支援规则，不再追踪或暂停来源动物。
- 数量牌包含已认领但未完成拾取的份数。认领只锁定份额，不提前扣数量；取消、休息、调岗或路径失败只释放该份认领，产物可再领取。
- 多个农夫可认领同一堆的不同份，不能争抢同一份。完成时一次性扣一份、增加金币、登记图鉴并扣体力，防止重复兑现。清空物品堆时也要正确处理剩余认领。
- 落地不提前记收益或图鉴，拾取自动结算且不弹确认。产物图案清楚可辨，数量牌只在堆叠时出现。

### 8.3 生产周期、互动、出售与旧档

普通计时成熟和互动提前成熟统一进入“本轮完成”处理：生成一份产物，立即开启完整的下一生产周期，增加周期编号并重置成年本轮加成额度。个人 120 秒、全局 2 秒互动冷却及既定加成上限继续有效。

已有地面产物不阻止新一轮互动加成。拾取只结算物品，不再重置动物周期或互动额度；掉落用来源动物与生产周期识别，避免同一轮被计时和互动重复生成。

出售动物按标准购价 50% 退款。已落地产物及其拾取任务保留，农夫可继续拾取；出售面板不再把它们作为随动物一并结算的收益。来源动物已不存在是合法状态，不能据此删除地面产物或判定坏档。

v4 存档保存动物当前循环、地面产物固定位置、数量、来源/售价批次及逐份认领。所有新增生产和鱼塘/农田布局变化统一在一次版本升级中校验。

- v3 中每只 `ready=1` 动物转成恰好一份地面产物，保留旧排队时间，同时按新规则启动下一轮。原档没有历史落点，使用加载时动物附近的安全点。
- 旧农夫收取任务由动物 ID 改为新产物及份额认领；行走中保留可通行当前位置后重新寻路，正在收取时保留剩余动作时间并校准有效落点。
- 清除旧收取造成的动物暂停/被持有状态，保留独立食物认领。未成熟动物保留生产剩余时间。
- 迁移不提前出售或登记，失败及重试不重复掉落；无效/重复认领释放后，物品仍保留可再次领取。

连续生产会提高无人拾取时的潜在产出，这是用户已确认的变化。本轮保留各品种原生产间隔、售价和食物消耗规则，验收时分别记录“已生产数量、地面待收数量、已拾取数量及收益”，核对守恒关系。
