# v0.7 验证与性能测量计划

本文件定义验证方法，不表示尚未执行的项目已经通过。正式玩家存档和正在运行的玩家进程均不得为了测试而覆盖或关闭。

## 自动检查

运行 `scripts/test.ps1`：先在本机发现可用 Python，执行独立工作簿数值核验，再执行 Godot 无图形导入、模拟/持久化、原生 API、控制器事务和界面、像素素材映射与缓存检查。没有 Python 时明确提示数值核验被跳过；也可通过 `-PythonPath` 指定解释器。

`-Suite Simulation`、`-Suite Native`、`-Suite Controller`、`-Suite PixelArt` 用于只复测发生变化的部分；默认`All`包含以上四组，已完成导入时可传 `-SkipImport`。`-SkipConfig` 仅跳过 Python 核验，不把跳过项报告为通过。原生API和控制器始终传入 `--benchmark-fixture`，原生互斥锁使用当前测试进程的独立名称，生产数据保持原版规则；测试只能使用 `.review/`、`user://test-data/` 或有专用测试名称的文件。

## 桌面与经营验收

静态场景缓存需用真实图形渲染器执行 `tests/test_raster_cache.gd`，不放进无图形All套件；该测试比较实际像素、命中坐标、缓存次数及隐藏恢复，不以dummy渲染器报告通过。

```powershell
& .\.tools\godot-4.7.2-stable\Godot_v4.7.2-stable_win64_console.exe --path . --script res://tests/test_raster_cache.gd -- --benchmark-fixture
```

- 普通启动不出现空白经营窗；所有经营页面内容完成后才显示。
- 种子和动物商店可从工具栏直达；搜索/分类/操作限制以最终界面实现为准，不能只验证菜单存在。
- 已有存档恢复后，自动购种、持续补种预留、50%标准购入价出售退款和图鉴登记结果保持不变。
- 用真实的另一进程窗口验证前后台切换：玩家点击其他应用后，该应用在所有农场窗口之前；收起/恢复后工具栏仍可操作，场景生产继续。
- 观察模式实际穿透，交互模式实际接收点击。只检查 HWND 的可见/置顶标志不足以证明鼠标路由或窗口遮挡正确。
- 收起后的经营面板必须比较实际新旧像素，避免原生可见但子 viewport 渲染停留在上一页的问题。
- 多显示器、125%/150% DPI、显示器移除及真实休眠作为单独的兼容性项目记录；合成 Windows 电源消息不能代替真实休眠结果。

## 发布程序性能

`tests/benchmark_release.ps1` 默认从 `project.godot` 读取版本，在当前仓库找到对应 `dist/DesktopFarm-v版本/DesktopFarm.exe`，每次生成带时间戳的证据目录。`-EnginePath` 可明确指定比较基线，`-ExpectedVersion` 可校验指定版本；`-PlanOnly` 只展示计划及发布文件是否存在，不启动窗口。

```powershell
# 先查看当前发布版的短测计划，无图形启动。
./tests/benchmark_release.ps1 -PlanOnly

# 根代理安排后的五阶段短测，每阶段测24秒。
./tests/benchmark_release.ps1

# 明确安排过的隔离并行测试，可保留已有玩家游戏继续运行。
# 旧发布版缺少隔离元数据时不支持此参数。
./tests/benchmark_release.ps1 -AllowParallelFixture

# 经短测确认可正常运行后，再安排指定模式30分钟长测。
./tests/benchmark_release.ps1 -Seconds 1800 -Phases ranch_30
```

五个阶段分别为农场30帧、牧场30帧、鱼塘30帧、农场省电15帧、收起30帧。每阶段独立启动正常PCK入口，预热2秒，使用96耕地、96草格、84动物、9农夫、12鱼的满规模隔离夹具。禁止用 `--script` 或 `--path` 替换发布程序入口。正式长期验收应覆盖全部五阶段各30分钟，单阶段短测或模拟时间推进不等同于长期运行验收。

CPU以实际发布进程的CPU秒增量除以墙钟和逻辑CPU数量，报告整机容量百分比；每秒记录WorkingSet和PrivateMemory，MB使用1,000,000字节。只汇总两个端点都处于测量阶段的连续样本；发布资源列出EXE、PCK和DLL的哈希。Release中引擎静态内存监视器可能为0，不能以其替代Windows进程内存。

默认采样器拒绝在检测到正式玩家游戏运行时启动，不终止玩家进程；异常清理只处理本轮`Start-Process`创建且PID与应用报告匹配的测试进程。正式存档仅比较运行前后存在状态及哈希，绝不写入。默认模式若另一个玩家进程在测试中途启动并改变正式存档，应中止存档未变的验收结论并注明并发活动。

明确传入`-AllowParallelFixture`时允许玩家继续运行，但仅接受新发布程序证明的隔离夹具：`benchmark_fixture=true`、`test_instance_namespace=Local\DesktopFarm.v07.test.实际PID`、`native_diagnostics.native_ready=true`、`native_diagnostics.test_instance=true`，并核验实际EXE路径、PCK入口和绝对保存路径为`user://test-data/benchmark-save.json`对应的专用测试文件。隔离字段缺失的旧包不得并行。结果注明并行模式及检测到的玩家PID，原始正式存档哈希变化只是观察，不能归因为测试，也不因玩家正常自动保存而判定测试失败；测试隔离证据仍必须全部通过。读取哈希遇到自动保存竞争时，记录观测不完整，不把两个不可读快照当作存档未变的证明。

结果区分运行有效性与性能目标：资源、夹具、时长、存档隔离和窗口可见性不符时检查失败；有效数据仍独立报告CPU<2%、峰值工作集<200MB是否达到，不能以平均值或达到帧率代替目标通过。15秒一次进度输出便于长测期间沟通。

## 当前热点证据与优化方向

以下为v0.6.1代码审查结论，最终v0.7需重新测量，不宣称任何预计节省已经实现。

| 观察 | 证据与意义 | 可行方向 |
| --- | --- | --- |
| 已有静态/动画分层 | `FarmView._draw`保留地面、建筑和文字；`_draw_animated`每帧重建动物、鱼及农夫 | 保留分层。像素图集使用稳定类型/动作索引，避免每个动物每帧创建调色字典与计算`hash([pattern,palette])` |
| 静态部分每0.5秒无条件重建 | 控制器定期`view.set_model(model.state)`，后者直接`_invalidate_scene` | 以可见场景状态或显示整秒变化驱动重绘；不得减少模拟步数或暂停后台生产 |
| 观察模式仍查询鼠标 | `FarmView._process`先`get_local_mouse_position`，再检查interactive | 不交互时跳过悬停扫描；观察/后台降低可视动画频率的收益需实测，默认流畅度不得悄悄改变 |
| 共享字体初始化会再次修改字体名 | 控制器将Theme字体注入FarmView，但FarmView的`_ready`增加`Noto Sans CJK SC`，名字数组不一致 | 仅在视图独立创建且未被注入时设系统字体名，保持真正共享资源 |
| 整个系统字体文件会被读取 | 本机`msyh.ttc`为19,701,556字节；Godot的SystemFont匹配后调用`load_dynamic_font`整文件读取 | 避免重复创建/改变SystemFont。若采用字体子集需有可分发许可证及完整中文字符覆盖，不以缺字换取内存数字 |
| 全Unicode预缓存没有应用代码证据 | 仓库未调用`font_render_range`或枚举所有支持字符；引擎普通绘字按索引调用`_ensure_glyph` | 不把工作集超标解释为全Unicode预缓存。字形缓存大小与独立窗口资源应通过同包A/B诊断取证 |
| 多窗口和驱动常驻开销仍可能存在 | v0.6短测收起时工作集仍263.74MB，而主场景draw calls为0 | 三个窗口/中文字体/驱动各自贡献尚未分离。考虑同样字体和窗口尺寸下的最小诊断程序，记录私有内存与工作集差值；不要用降低渲染次数直接推导等额内存下降 |

字体相关实现依据为官方Godot 4.7.2源码：[SystemFont更新与FontFile读取](https://github.com/godotengine/godot/blob/4.7.2-stable/scene/resources/font.cpp)、[TextServer的按字形绘制与显式范围预渲染](https://github.com/godotengine/godot/blob/4.7.2-stable/modules/text_server_adv/text_server_adv.cpp)。这些实现证明加载和缓存方式，不证明本项目每个来源的实际内存占比。
