# 桌面农场开发规格 v0.6

日期：2026-09-30，2026-10-01更新。目标：Windows 11 x64 本地试玩版。本文是程序实现与验收的直接依据，继承 v0.5 设计和数值，并纳入本次用户确认的变化。像素风已确认；首次交付使用原创程序绘制的占位精灵。正式素材和商业发布不属于本次试玩版交付。

## 1 基线与规则优先级

用户在本次对话确认的规则优先于 v0.5 冲突文字。其余玩法按原设计实施。结构化配置 `data/production.json` 保存固定成熟时间、价格和扩建费用；不在运行时重新计算收益档位，不以平均售价出售随机产物。

| 已确认项目 | 开发规则 |
| --- | --- |
| 动物出售 | 按品种标准购入价的50%向下取整退款，赠送动物相同；释放棚位 |
| 图鉴 | 作物、动物产物和鱼都可登记；作物、动物产物收获后自动登记并出售 |
| 鱼图鉴 | 鱼捕获后选择出售或登记；登记消耗该鱼，不另出售、不放回 |
| 延迟换种 | 各格完成本轮后分别换种；目标种子预算持续保护，可取消释放未生效预留 |
| 平台与素材 | Windows 11本地试玩版、像素占位素材 |
| 运行时间 | 最小化、收起、锁屏继续；进程退出和系统休眠暂停；不补离线收入 |

工程默认由本次开发采用：幼崽和成年同退款比例；卖动物时先结算已有待收产物一次，再取消其任务并出售。鱼待选择状态持久化且阻止再次出网。正常加载恢复有效农夫任务，仅取消无效认领。取消换种不回滚已经换种的格。

## 2 技术与项目结构

- Godot 4稳定版、类型化GDScript、Compatibility渲染。具体引擎和编译器版本记录在 `.tools/toolchain.json`，首次下载后锁定。
- 小型C/Win32 GDExtension处理场景整窗穿透、无焦点显示、工作区、休眠通知、有效运行时间及单实例。
- 场景窗与工具栏窗独立。观赏时场景可见而鼠标穿透到其他应用，工具栏保持可点；互动时场景接收浇水/捕鱼输入。
- JSON配置和本地存档；逻辑不依赖绘制和系统真实日期。生产模型可用Godot headless独立测试。

| 路径 | 职责 |
| --- | --- |
| project.godot / scenes/main.tscn | 引擎配置和入口 |
| scripts/main.gd | 控制器、菜单、操作事务、自动保存 |
| scripts/game_state.gd | 全部生产逻辑及经济状态 |
| scripts/save_store.gd | 原子存档、备份、读取和版本验证 |
| scripts/farm_view.gd | 像素精灵、三个场景、命中区域和分页 |
| scripts/desktop_host.gd | Godot窗口与原生桥接、有效时钟 |
| native/ | Win32扩展源码、官方ABI头文件与构建脚本 |
| data/production.json | 53作物、11动物、7棚、3鱼和75个产物 |
| scripts/export_config.py | 原始数值导出工具 |
| tests/ | 配置、模拟、事务和桌面验收 |
| dist/ | 可运行试玩版及运行说明 |

Godot的Windows局部鼠标穿透多边形会裁去多边形外的画面，不能用该方式实现可见场景穿透。以实际导出程序验证原生层，不将编辑器内嵌窗口行为当成验收。

## 3 窗口与像素界面

基准为1920×1080、100%缩放、底部240逻辑像素，窗口贴任务栏上方工作区下缘。顶部32像素工具栏，8像素间隔，172像素场景，8像素间隔和20像素状态栏。高DPI按逻辑像素布局；窄屏按区域或模块水平翻页，不把字和操作缩到难辨认。

视觉采用轻俯视2D像素风。颜色为草绿、土棕、米白、浅蓝；人物和动物有小幅移动及工作反馈，图形使用整数坐标和最近邻采样。中文菜单使用系统字体，保持清晰。生长阶段、未浇水、成熟、饥饿、母草、仓满、锁定格有明确区别。

实现将静态背景、地块、棚舍和说明文字保留为缓存绘制命令，随状态约每0.5秒更新；农夫、动物、鱼和水纹使用独立CanvasItem，保持30帧或省电15帧动画。工具栏与菜单脱离主场景视口的渲染依赖，收起场景时仍可绘制。

工具栏入口：种植园、牧场、鱼塘、种子商店、动物商店、经营；经营提供商店、扩建、农夫、图鉴和设置入口。显示余额、补种保护额、可投资额、互动/观赏、翻页和收起。购买面板默认隐藏，点击入口后完成内容和位置设置再显示，Esc/关闭按钮关闭。种子商店显示价格、库存、解锁和区域选择；沿用播种时先用库存、用完自动购种的机制。初始可投资额为520，额外300牧草建议仅作为建议，不自动扣款。

依据用户试玩反馈，v0.6.1的场景、工具栏和经营窗口一律采用普通Windows前后顺序：点击其他应用后，其他应用显示在游戏前方；不提供永久置顶开关。旧存档的topmost=true自动忽略并在后续保存中更新，生产状态保留。后台刷新布局、切换输入及重复显示不得抬升已显示的窗口。设置提供15帧省电、位置重置、保存重试和明确退出。收起继续运行，只隐藏场景；退出保存后结束进程。显示器移除或分辨率变化时返回可见工作区。单实例程序再次启动时不创建第二份生产状态。

## 4 开局及生产

初始1000金币、24防风草种子、4区各6格、一级鸡窝和4幼鸡、6格4簇草其中2母草、食槽8干草、三个场景各1农夫和12鱼。赠送不扣款，不推进付费招聘序号。开局保护480金币。

每格作物保存实际crop_id和状态：空地、播种动作、未浇水、生长、成熟、收获动作、加工。农夫播种、浇水和收获各2秒动作，另计固定1秒的同场移动预算；缺钱或资源不足的任务等待。当前占位人物按任务目标定位并显示工作反馈，同场路径及完整行走动画留待迭代。成长从浇水完成开始，工人休息不停止已浇水成长。用户水操作不扣精力，并撤销对应未提交自动任务。

单次收1份卖出并补种；连收留株，下轮浇水后开始首熟三分之一的间隔；向日葵42分钟返一枚原格专用种，换种后不能转移；稻谷成长27分钟、收获后串行加工3分钟再卖米100，期间地块不补种。混合包与四季野种每轮抽一份具体产物，按包时间成长，持久化随机状态和结果。

春季及表中默认开放作物免费；其他一次解锁，解锁后全年种。每区目标作物相同，延迟切换期间可暂时混种。新开区域、加格和换种检查首批及下一轮需要的种子预算；库存按稳定地块顺序分配，不重复抵扣。连收留株及已有专用返种下一轮成本为0。

## 5 牧草与动物

每180秒对本轮已有草快照增长：均匀1至3封顶4，再65%判定；未满时加均匀0至2，已满时四邻空已开格各25%扩散1至2。结果统一提交，新草不级联，多来源命中累加封顶4。母草不吃不割，普通草保留1簇。

每餐300秒，小动物2簇、大动物4簇，可跨草格凑足完整一餐；不足则吃食槽1干草，不扣半餐。幼崽也进食。饥饿暂停成年和产物进度，无死亡或倒退；已成熟产物可收取。动物成年后开始首个生产周期，每只最多积压1份，收取后才重启。

割普通满草3簇为1干草；草仓与食槽分别24/64/128/256容量，共同升级。添草每次最多4份，草仓不足或食槽满时不执行。饥饿/低粮优先添草，再割草；普通状态先收产物，再补草，最后播草。买动物要求棚级及空位；卖出原子结算产物、退款、释放棚位并保存。

零金币自动恢复仅在仍有可生产动物时验证；若玩家已卖光动物且无种子金币，可以免费自然补鱼及手动售鱼恢复。

## 6 农夫调度

每场景本岗最多3人，总9人。6次付费招聘全局共享1000、2000、4000、8000、16000、32000序号。免费转岗不重置报价。目标本岗和在场/入场预留都校验，活动任务或跨场途中不立即转岗。

精力上限100，工作与移动不恢复，空闲/休息每秒2；不够下一项任务时回本岗休息至满。播种2精力，浇水/收获/割草/添草/收动物产物1，播草2。一个对象只有一个有效任务认领，任务完成才扣普通精力并提交；取消释放未提交资源。

种植园按收获、浇水、播种和进入队列顺序。支援只有本岗无有效任务且满精力时发起，预留目标名额后出发扣20，步行5秒；返岗免费。目标驻岗加支援不超过3。本岗来任务或精力不足，完成当前动作后返岗；返岗优先撤访客，避免双方互等。鱼塘农夫不自动捕鱼。

## 7 捕鱼与图鉴

鱼初始及上限12，每180秒补1，满池冻结剩余补鱼时间。小银鱼/青背鱼/金纹鱼概率25%/50%/25%，售价30/50/70。没有饲料、自动捕获或自动收入。

互动时点/短拖命中最多1鱼，出网冷却20秒，未命中同样冷却。捕获后保存pending_fish的ID、种类、价格，暂停出网。玩家选出售或登记图鉴后只提交一次。切场/收起/退出不遗失待处理鱼。图鉴按真实产物ID累计获得次数；作物和动物收获自动登记，鱼登记依玩家选择。

## 8 时钟与存档事务

原生有效时钟排除系统休眠。游戏按1秒子步结算，保存分数秒；草180秒批次。普通调度延迟补算仍在运行的有效时间，休眠和离线不补。到期生产、草更新、进食、动作提交和派工使用稳定顺序；边界不多推进饥饿时间。

自动生产每30秒保存；用户购买、解锁、扩建、出售动物、转岗、捕鱼处理、设置和正常退出立即保存。用户事务先保存操作前快照，命令成功后写完整新快照，落盘失败则恢复操作前快照并提示。普通进度强制终止最多损失30秒。

保存写临时文件、flush、校验JSON、保留上一完整备份并原子替换。加载验证版本、ID、非负资源、容量与任务；主档坏则尝试备份，两份均坏保留文件并提示，不偷偷重置。旧版本升级必须显式迁移并留版本备份。完整状态包括配置版本、金币、每格作物、库存/预留、草、动物、农夫动作与跨场预约、鱼、图鉴、随机流及窗口设置。

## 9 验收与交付

配置核验必须覆盖53作物、11动物、7棚、3鱼、随机池、全部878725扩展费用、480保护/520可投和赠送4鸡出售1600。核心headless测试覆盖特殊作物、跨区库存、持续预留取消、草快照、饥饿暂停、任务锁、招聘序号、支援返岗、鱼待选择重载和损坏存档回退。

实际桌面验收：透明场景仍可见且点击到外部应用；工具栏按钮可点；互动浇水/捕鱼；125%和150%缩放；任务栏避让；显示器移除；休眠前后剩余时间；收起继续/退出停止；单实例；导出试玩版运行。

性能目标为平均CPU不超过2%、峰值进程内存不超过200MB；实际短时观测和未达项目记录于验收报告，不把目标当作实测成绩。满规模96作物、96草、84动物、9农夫、12鱼分别测试可见30帧、省电15帧、最小化30分钟；记录测试机、私有内存/工作集、CPU统计口径和计时漂移。目标不能用空场成绩代替。

交付物为开发文档、完整源码、可运行Windows试玩程序、启动/测试/构建脚本及验证记录。阶段顺序：窗口与时钟原型→可保存种植闭环→完整作物→牧场→人员协作→鱼塘图鉴→满规模验证。实际已通过与待人工验证项写入 `docs/validation-report.md`，不得将未测项标为通过。
