# 桌面农场 v0.8 开发方案（需求确认版）

日期：2026-10-01。依据本轮试玩反馈编写，基线为 v0.7.0（207a8f8）。本文安排下一轮实现与验收；目前交付的是方案、数值建议和视觉概念图，应用运行规则尚未改变。

## 1 本轮目标与确认范围

| 用户明确提出的内容 | 下一轮设计 |
| --- | --- |
| 农夫移动过快，希望可控 | 匀速行走，设置速度范围；按真实距离到达后开工，速度影响效率 |
| 动物自由移动、觅食 | 棚舍管理容量与归属，动物在公共牧场内游走、寻草和进食 |
| 牧草自然生长 | 用不规则草斑表现增长、扩散及吃掉后的稀疏状态 |
| 动物点击互动与成熟加成，限制频率 | 幼崽成长与成年本轮产出均有加成，保存每只动物冷却和累计额度 |
| 渔网及鱼塘数量升级 | 两条独立升级线，各三次；具体价格见第7节 |
| 土地景色丰富，减少文字 | 连续自然地形、土路、树荫、石块和田边；详细信息按需展开 |
| 取消6区域，每小块独立种植 | 每格独立种植偏好、换种计划与扩建；支持框选批量操作 |
| 购买种子入库，耗尽使用默认自动订购种子 | 商店增加数量购买、种子库和全局默认种选择；整个可用种子库耗尽后才自动订购 |

用户已确认：整个种子库用完才自动订购，其余种子按固定顺序继续种；幼崽及成年均有受限互动加成；农夫按实际距离行走，到达后开工。原品种价格、成熟时间、产量、图鉴及动物50%标准价退款沿用现有数值；真实行走、觅食和互动会改变实际经营节奏，需要在实现后对照旧版测量。

## 2 农夫移动与速度设置

当前 `farm_view.gd` 的行走插值固定0.85秒，任意距离都在同一时间走完。移动36像素约42像素/秒，移动1000像素约1176像素/秒。模型另按固定移动1秒加动作2秒计时，画面与作业并未共享位置。

建议增加稳定的世界位置、路径与行走阶段。默认速度32逻辑像素/秒，设置范围16至48，步长4；32像素地块相邻距离约1秒。DPI、窗口宽度、翻页和帧率只改变显示，不改变世界距离。

已确认的流程为：认领任务与资源 → 按路径匀速走到作业点 → 原有2秒动作 → 一次提交结果。远处任务会花更久，优先级仍先收获、再浇水、再播种，同级按等待时间处理；可用距离作为同等待级的稳定次序，避免无必要的折返。途中调整速度从当前位置生效，不瞬移或重做已经提交的动作。

模型位置随有效游戏时间推进，渲染在模型位置之间插值。保存位置、路径目标、任务阶段及剩余动作时间。隐藏后继续工作，恢复显示时读当前状态。跨场支援保留名额预约与5秒切场预算，本轮速度设置作用于同场行走。

## 3 独立地块、种子购买与默认自动订购

### 地块与操作

初始24块、最多96块。去除区域对象、区域统一作物和区域解锁门槛，改为一个连续农田中的独立可开垦位置。初期使用预设位置，支持单选、框选、多选以及批量安排种子，避免逐一点击96块地。

每块地拆分三类状态：

- `crop_id`：当前实际作物，用于成长、产物与结算。
- `preferred_crop_id`：长期种植偏好；建议补回这种库存后再次优先使用。
- `pending_crop_id`：本轮结束后生效的换种安排，等待期间持续预留，允许取消。

点击种子库中的品种后选择地块。空地可马上排入播种队列；已有作物等本轮收获完成，水稻等加工完成后再换种。设置计划不改变当前生长作物、剩余时间或已抽中的随机产物。

### 商店和播种来源

种子商店保留品种解锁，增加1/5/10/25枚购买和自定义数量。购买一次扣款，实际种子进入库存；购买不同时种植。种子库显示图标、可用数量、已预留数量和选中品种。

商店提供“默认自动订购种子”，初始为防风草；只能选择已经解锁的品种，提交前预览补种保护额变化。不同地块可以有不同偏好，全场共用一个默认订购品种。

建议每次播种按以下顺序确定唯一来源：

1. 与本格当前计划匹配的原格专用返种。
2. 已绑定本格的待换种种子预留，转交任务而不再次扣库存。
3. 本格偏好作物的可用库存。
4. 按种子库固定顺序取第一种其他可用种子。
5. 整个可用种子库均为0时，购买一枚全局默认种，经过库存机制预留给本次任务。

本格偏好品种库存为零时，继续使用库中其他种子，不立即自动购买默认种。固定顺序取当前 `production.json` 的作物列表顺序，种子库面板同序显示，不随购买时间、搜索或排序临时变化。播种前提示下一枚实际来源，例如“库存轮转：胡萝卜”；库空时才提示“自动订购：防风草”。自动购买按实际需要进行，不提前成批扣款。

“库用尽”指未预留的通用种子库存为0。已被其他任务领用或为待换种地块预留的种子不可再分配；该地块已有种子预留时不能重复下单。原格专用返种另行处理，不计入通用种子库。明确换种优先为该地块预留对应库存，取消后释放；其余播种只使用未预留库存。预留账本绑定 `plot_id / crop_id / quantity / purpose`，新买到相应品种的库存先满足既有待换种预留缺口，再开放给普通播种使用。未能预留目标种的计划在播种前依上述全库轮转规则选实际种子并提示玩家。

已预扣的播种种子和任务实际品种固定。之后修改默认种或偏好不改写已认领的种子；取消未提交任务退种子回库存。取消换种释放未生效预留，已经购买的库存仍保留。

### 特殊作物

再生作物继续留株，无需新种子，不因库存耗尽被自动拔除；明确预约其他作物才在收获后替换。向日葵专用返种仅用于原格，换种后失效。水稻加工结束、成品售出后才补种。混合包保留包的品种与成熟时间，实际抽中产物独立保存。

## 4 自然土地景色与信息布局

![自然田园概念图](design/natural-farm-concept-v0.8.png)

概念图由内置 imagegen 生成，原图2172×724，是美术方向预览。实际程序仍使用底部桌面条、种植园/牧场/鱼塘切换；分别采用同一套地形语言。完整提示词见 [生成记录](design/natural-farm-concept-v0.8.prompt.md)。

自然地形采用连片干湿泥土、不规则草岸、土路、木栅边缘、小石块与野花，树和棚舍安排在边缘。作物、动物、人物尺寸保持一致。独立地块的耕作边界可辨认，悬停/选中时才突出操作范围；未开垦位置表现为自然地面。

常驻场景文字收敛为余额、必要操作与异常提示；缺水、成熟、饥饿用小图标表达。品种名称、剩余时间、成长比例、库存预留和互动冷却在悬停提示或点击详情中查看。建设价格、生产收益和完整解释放进经营面板。

实际实现使用小型地形图集、共享精灵和静态缓存，整数像素绘制与最近邻采样。概念图拆解为素材需求与布局参考，不将整张大图载入游戏充当地图。树荫和装饰避开可操作地块，命中范围与实际显示位置一致。

## 5 自由放牧、自然草斑与觅食

棚舍继续决定可购动物品种、级别和容量，每只动物保存归属；动物可离开固定畜栏，在公共牧场的可走地面活动。状态包括闲逛、停留、寻草、前往食槽、进食和等待照料。小动物建议12逻辑像素/秒，大动物10，采用软避让，避免拥挤形成硬堵塞。

牧草采用不规则草斑，随密度变化显示疏密、断边和连接，取消可见草格线框。内部保留最多96个可生长采样点用于容量、空间索引与确定性结算，开放草地的扩建沿用现有草地成本。位置扰动与外观变体固定于存档种子，重载不重新排列。

延续每180秒增长、每点最多4簇、快照提交、增长与扩散概率。两处起始母草保护斑持续扩散，普通草吃/割后留1簇草根；新生成的草本轮不继续级联扩散。每个点的生长概率与四邻可扩散邻接保持原规则，本轮原有草增长到4簇也可进入扩散分支，外观连接由草斑图块表达。

动物每300秒需要一餐，小动物2簇、大动物4簇，幼崽同样进食。普通满草留下草根后可吃3簇，大动物需要至少两个可达草点，不能要求单点独自供应4簇。

真实觅食建议提前最多120秒寻找完整一餐并预约草量，按附近且可达的草点规划路线；到草边才能进食。预约与农夫割草共用一份资源账本，避免两只动物同时吃掉同一簇或割草删掉已约草量。跨点整餐统一结算，不扣半餐；进食动画可以在多个目标点表现。

没有足够可达青草时前往食槽，消耗1份干草。无法及时到达或无粮则饥饿，暂停成长/产出，保留既有成熟产物。草目标失效时重新规划；取消寻草、出售动物或预约超时都释放未消费资源。饥饿不停止移动与寻粮，吃到完整一餐后解除饥饿并重新计300秒餐间隔。相较旧版全场直接取草，路径和可达性会改变实际进食与干草消耗，这是需要实测的新规则。

农夫收取移动动物的产物时，动物进入短暂等待照料，农夫到达后完成原2秒动作，避免持续追逐。本轮不引入日夜时钟；棚舍继续提供入口、归属和容量用途。

## 6 动物互动与成熟加成

幼崽与成年阶段均加成已获确认；以下频率与额度为建议试验数值：

| 项目 | 建议规则 |
| --- | --- |
| 同一动物奖励冷却 | 120秒有效游戏时间 |
| 全局奖励操作间隔 | 2秒，避免连点或重叠命中多次记账 |
| 幼崽每次有效互动 | 剩余成长时间减少最多30秒 |
| 幼崽累计上限 | 该品种标准幼年时间的20%，同一实例仅一份 |
| 成年每次有效互动 | 剩余产出时间减少最多标准周期的5% |
| 成年每轮累计上限 | 标准生产周期的10% |
| 饥饿或产物已经待收 | 有轻量反馈，不发经济奖励 |
| 数值下界 | 剩余时间不低于0，不增加产量或售价 |

每次实际减免取“建议减免、剩余时间、尚可奖励额度”的最小值。一次互动仅奖励当前阶段，不把幼年溢出加成带入首次产出。幼年转成年、产物收取或切场均不重置同一动物的120秒冷却；成年累计额度只在本轮产物收取后重置。限频、额度和周期序号入存档，退出/休眠不推进冷却。

鸡的标准幼年900秒，最多减180秒，最早720秒成年。标准产蛋300秒，成年两次各减15秒、最多减30秒，周期最早270秒。两类奖励都满足时首次产蛋最早990秒（16分30秒），原基线1200秒（20分钟）；这是忽略饥饿与收取延迟的理论下界。

成年周期减少10%对应最高长期产出增益约11.11%，因此不再另加售价/额外产量。

## 7 渔网与鱼塘升级价格

三个鱼种概率25%/50%/25%、售价30/50/70，平均售价：
`0.25×30 + 0.5×50 + 0.25×70 = 50`金币。

价格均为到达该档的单次增量扣款，依次升级，网与塘独立：

| 档位 | 渔网冷却 | 网升级费 | 鱼塘容量 | 塘升级费 | 空塘补满时间 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 初始 | 20秒 | 0 | 12条 | 0 | 36分钟 |
| 一级 | 15秒 | 200 | 18条 | 300 | 54分钟 |
| 二级 | 10秒 | 400 | 24条 | 600 | 72分钟 |
| 三级 | 5秒 | 800 | 36条 | 1800 | 108分钟 |

网价格为 `4×平均鱼价×2^(升级序号−1)`，对应4/8/16条平均鱼价值；容量价格为 `平均鱼价×新增容量×升级序号`，按储存价值与成长档位定价。网满级累计1400，塘满级累计2700，合计4100。

首档两项合计500，按开局1000金币、480补种保护、520可投资可以买得起。升级仍校验实时可投资额，不占用受保护的种子预算。

每180秒补1条，一网最多1条，未命中也冷却；捕获后仍选择出售或登记，处理前阻止下一次出网。升级不改变鱼种概率、售价和补鱼间隔，不赠鱼或重置当前倒计时；升级容量从现有剩余补鱼时间继续，升级冷却应用于下一次出网。

网升级改善集中捕鱼速度，塘升级延长蓄鱼窗口。长期供给上限仍是20条/有效运行小时，全部手动出售的期望1000金币/小时；无人捕获的实际收入为0。12/18/24/36条满塘期望售价为600/900/1200/1800，均为概率期望，不是固定收益或保证回本。

后续若希望提高产鱼速度，应单独增加繁殖升级和相应经济测试；本轮不自动叠加。

## 8 单块开垦与保护额

取消区域费用后，建议把旧满规模开垦总额平摊到连续的单格递增曲线：
`6×(350+700+…+3500)+10000+20000 = 145500`金币。

第25格350，第96格3692，中间每次增加47或48。72项价格由350至3692等差插值四舍五入，按最大向上舍入误差顺序将12项各减1，整数合计145500。配置已有完整建议数组；报价取当前已开放数量，不依赖原区域。旧存档保留已开地，不补扣/退款；145500仅描述新局完整扩建。

保护额先识别已领用及显式待换种的种子预留，再使用一份可用库存副本按稳定地块顺序虚拟分配：待播首批优先，再算需保护的下一轮。播种来源与实际规则一致，优先指定品种，再按固定顺序使用其他库种，整个可用库空了才按默认种价计入金币缺口。每枚库存只抵扣一次；已认领且预扣种子的首批请求跳过，避免再次计算。

普通空地考虑首批及下一轮；正在成长的单次作物考虑下一轮。尚未生效的换种以新计划首批及下一轮替换旧需求，持续保护，可取消。留株再生和原格专用返种按原机制免除对应补种成本。指定种库存不够时，先继续分配其他未预留库存，剩余缺口才按默认种而非缺货品种计算。预测首批实际使用再生种或向日葵时，后续预算也按留株或原格返种计算，不能继续假设全是防风草。

确定例子：24空地、24防风草库存，首批全用库存，下一轮缺24枚×20，保护480；农夫已预扣1枚、库里剩23枚时，跳过该任务首批，保护仍480。购买24枚防风草花480，余额从1000变520、库存从24变48、保护从480变0，可投资额仍520。

购买库存应模拟“扣款+增库存”后的保护额再校验，不能简单要求种子购买金额小于操作前可投资额。建设、动物购买及鱼塘升级则检查扣款后余额覆盖保护额。

另一个确定例子：24格正在长防风草，库中只有1枚胡萝卜和1枚花椰菜，无其他预留；下一轮先用这2枚库存，只为其余22格保护 `22×20=440`，不因缺少防风草种子提前下单。如果其中花椰菜已绑定一块待换种地，而胡萝卜仍可用，按换种首批加下一轮保护：其余23块用胡萝卜1枚、订单22枚，换种格首批用预留花椰菜、随后需订单1枚，共保护460。不能重复收费那枚花椰菜，也不能漏掉换种后的下一轮。

更换全局默认种即重算未来未认领订单。24格正在长作物、库存为0时，从20金币防风草改80金币花椰菜，下一轮保护从480变1920；余额1000则拒绝本次变更，全部状态不变。允许恢复先前默认种，并重新校验预算，已播作物和已预扣任务照常完成。如果该例另有上述2枚库种可用，改花椰菜只保护剩余22格，即1760，仍超过1000余额而拒绝。

## 9 技术拆分、存档迁移与性能

继续使用现有Godot和Win32桌面层。在当前大文件之外拆出种植计划/库存分配、世界移动/预约、牧场觅食、互动额度和鱼塘升级模块；`game_state`仍统一提交经济事务，视图只绘制和处理命中。

存档升级为v2：先验证v1并保留不可覆盖的迁移备份 → 内存转换 → 验证v2 → 原子保存。迁移失败保留原档，不建立新局。

保留金币、实际作物、进度、库存、图鉴、动物成长/产物、随机流和有效任务。旧区域未完成换种展开到对应未完成地块，已换种格不重做。稳定ID保留，原地块位置映射为新世界位置，原先没有持久化坐标的农夫/动物在对应作业点或棚舍入口初始化；渔网与鱼塘等级初始0。已付款/预扣播种任务保留实际种子与剩余工作，不重复收费。旧草量与母草标记保留并映射到草斑。迁移先恢复播种任务领用，再为旧待换种计划建立对应库存预留，最后开放剩余库种供自动轮转。

新增保存字段包括默认种、每格偏好/计划、世界坐标、任务行走阶段、草/干草预约、动物觅食状态、互动冷却/额度/周期、网等级和塘等级。各种来源只允许一次结算，人工命令仍即时原子保存。

地图碰撞与空间索引缓存；寻草/选路仅在目标变化、无路或低频决策时更新。移动逻辑建议5Hz固定步长，渲染30/15帧插值，生产继续采用有效时钟和原有稳定结算顺序。每帧不重建路径或扫描84动物×96草点。隐藏时停绘制，保持计时与生产。

原性能目标仍为CPU平均≤2%整机容量、峰值工作集≤200MB。v0.7牧场实测约2.029%、274.76MB，已有差距；本轮要重新测96地块、96草点、84动物、9农夫和36鱼，优化结果以实测报告为准。

## 10 开发顺序与验收

| 阶段 | 可试玩交付 | 必须验证 |
| --- | --- | --- |
| A：种植与画面基础 | 独立地块、种子数量购买/种子库、默认订购、匀速农夫、自然地形、v1迁移 | 混种、库存耗尽、任务预扣/取消、预算、特殊作物、旧存档恢复、DPI不改变产能 |
| B：牧场生活 | 自由游走、草斑增长、真实觅食、互动加成与冷却 | 多动物预约同草、大动物跨草点、割草冲突、无粮暂停、路径失效、互动重复/重载/跨周期 |
| C：鱼塘及整体验收 | 两条升级线、经营入口、低文字状态提示、v0.8试玩包 | 价格/等级/容量校验、补鱼/冷却不被升级重置、待处理鱼一次提交、满规模性能与窗口回归 |

阶段A先稳定种子与经济闭环，后续阶段复用世界坐标和预约机制。每阶段都提供独立可试玩包和变更说明，完成三阶段后定为v0.8.0；不直接把三个大系统一起替换后才验收。

重点桌面回归包括点击其他应用优先显示、启动无空白框、托盘/快捷键/全屏隐藏、观赏穿透、隐藏继续、退出停止。所有测试采用隔离存档，保留玩家正式存档。
